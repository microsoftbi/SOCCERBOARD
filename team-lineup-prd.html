概览

把一支球队的「上几个人、谁上、站哪儿、长什么样」，在开播前变成一张导播可直接使用的赛前站位图。

要解决的问题

赛前球队介绍画面目前依赖人工排版：制图人员拿到一份手写或聊天记录里的名单，在图像软件里摆 6、8 或 11 个点位。改一个号码就要重做整张图，位置标签靠记忆，队长经常漏标。

业余、青训与低级别职业赛事没有专职制图人员，名单往往在开赛前几十分钟才到齐。错号、错位、漏队长会直接出现在直播画面里，且没有二次检查的机会。

产品定位

主要用户
转播制作人员 / 导播助理。单人操作，每队 10–15 分钟内录完。
使用时机
赛前名单确认后、开播前，按主队、客队各建一份档案。
核心任务
录入人数与球员信息，编排场上位置，生成可交付的赛前站位图。

确认名单真实、指定队长、决定谁站哪个槽位、确认导出结果符合播出规范。

球队档案（Team Sheet）。两份档案（主/客）共同构成一场比赛的介绍素材。

设计与流程

四个步骤对应四种心智负担：确定规模、填人名、摆放位置、确认画面。每一步都可以回退，且不丢失已填内容。

核心流程

01 建档案：身份·人数·阵型→ 02 逐位录球员：号码·姓名·位置·队长·照片→ 03 编排槽位：自动落位 + 手动调整→ 04 预览与导出

触发：名单确认后，操作员在主队/客队档案上点击「开始录入」。完成：站位图导出成功并通过全部校验。回收：任意步骤都可返回修改，修改后校验重新计算。

最重要的一条恢复路径：人数从 11 改为 6 时，系统不删除已录入的球员，而是把多出的球员移到替补席，并保留全部姓名、号码与照片；切回 11 人时可重新落位。

关键产品决策

先定人数，再录人

人数不是画面参数，而是名单的容量约束。先定人数，录入阶段就能即时显示「已填 4 / 6」，并把校验标准固定下来；否则要到出图时才暴露缺人。

位置与槽位分离

球员的信息里存「主位置」（如 CDM），槽位上存「本场位置」（如 RCB）。同一个人在不同阵型里站的位置可能不同，两者不能合并；自动落位只做建议，最终以槽位为准。

照片允许缺失，但必须有降级

业余赛事常拿不到标准头像。缺图时不阻塞流程，站位图用球队主色底 + 球衣号码占位，与有头像的球员视觉重量一致，避免画面出现空洞。

不自动决定队长

队长由操作员显式标记，系统只保证「最多一人」。系统不根据出场时间、位置或历史数据推断队长。

导出静态画面而非动态组件

本期交付物是一张图与一份结构化名单，不接管直播渲染。这样系统可以脱离直播软件独立使用，也避免与导播台耦合。

界面与状态

桌面端左侧为操作区（导播端），右侧为本文档。四个页面共用同一份档案状态：身份、人数、阵型、球员列表、槽位、视角与显示项。切换页面不重置任何数据。

功能明细

按用户任务组织，每一项都对应原型中的一处可操作界面。

F1 比赛与人数设置

进入系统后的第一屏。用户在这里确定本场是谁、上几个人、默认怎么站。此处的选择直接决定后续录入的行数与可选阵型，因此必须在录人之前完成。

操作与响应

  1. 选择本场身份「主队 / 客队」。同一比赛内两份档案可同时存在，身份影响站位图上的队名位置与出场顺序，不限制功能。
  2. 填写球队全称与三字代码。三字代码用于窄屏字幕与图角标，超过 4 个字符时截断提示。
  3. 选择球队主色。该色用于站位图球员缺图时的占位底色，以及字幕条的主色块。
  4. 选择场上人数：5、6、8、11。切换时立即重建阵型下拉与录入行数，并显示「决定阵型库」说明。
  5. 选择默认阵型。下拉只列出与该人数匹配的阵型。

规则与边界

  • 人数切换不删除已录入球员：减少人数时，末尾的多余球员转入替补席；增加人数时，空行追加在名单末尾。
  • 三字代码为空时允许保存，导出图角标退化为球队名称首字。[Assumption, TBD]
  • 球队全称为空时不允许进入下一步，提示「请填写球队名称」。
  • 主客两队主色相同或过近时，导出前给出提醒，但不阻断导出（真实球衣可能确实接近）。

F2 球员逐位录入

录入区按「一人一行」排列，行数等于场上人数。操作员按号码顺序逐位填写，这一过程必须能单手快速完成，且随时知道还差几个人。

每一行的字段

字段输入方式必填说明
号码数字，1–99是唯一；与已填号码冲突时该行标红并给出具体冲突对象。
姓名文本，2–20 字是站位图标签显示；过长时标签省略，导出名单保留全名。
位置下拉，按人数过滤是表示球员主位置，用于自动落位建议，不等同于最终站位。
队长圆形开关，全档案唯一否标记新的队长时，原队长自动取消，不会出现两人同时为队长。
照片本地文件选择否见 F3。

进度与校验

顶部实时显示「已填 x / n」，x 以姓名与号码均非空的行计数。点击「校验并进入站位编排」时按顺序检查：姓名缺失 → 号码越界 → 号码重复 → 无门将 → 队长多于一人。只展示第一个未通过项，并定位到对应行；全部通过才进入下一步。

边界

  • 删除一名球员时，若该球员已占用槽位，槽位同时清空，并提示可撤销。[Assumption, TBD]
  • 增加的行默认为空，不参与校验，也不出现在站位图。
  • 录入过程中切换人数，已填内容按行序保留，不重新排序号码。

F3 球员照片

照片是赛前介绍画面的视觉主体，但拿到标准头像并不总是可行。设计目标是：有图时整齐一致，无图时不出现空洞。

行为

  • 每行提供一个方形上传位。可从本地选择图片，选择成功后立即显示缩略图。
  • 再次点击可替换；悬停显示「替换」提示。
  • 照片按 1:1 居中裁切，站位图内以圆形呈现，不改变原文件比例。
  • 未上传时，上传位显示「+ 照片」，站位图用球队主色底 + 白色球衣号码代替。

边界

  • 非图片文件或读取失败：保留原有照片，提示「该文件无法作为照片使用」。
  • 照片缺失不阻断导出，仅在导出前汇总提示「n 名球员未上传照片」。
  • 照片尺寸上限与压缩策略。[TBD]

F4 队长标记

队长是解说与字幕必提的信息。系统把它做成「互斥开关」而非自由勾选，避免两人同队的播出错误。

  • 每行有一个队长开关。点击某球员后，其余球员的标记自动取消。
  • 再次点击同一球员即取消标记，允许「暂未指定」。
  • 站位图上，队长在头像右上角显示字母 C 的黄色圆标，一目了然。
  • 校验不要求必须指定队长，但在导出前提示「尚未指定队长」。

F5 阵型站位编排

用户的核心动作不是描述位置，而是「把人放到位置上」。画面上呈现的是真实俯视球场，槽位由所选阵型预先确定，球员从替补席被放入槽位。

落位方式

  1. 自动落位：按球员主位置与槽位位置的对应关系，一次性把所有未落位球员填入最近的空槽；填不满时保留空槽并标为虚线。
  2. 手动落位：点击一个槽位使其进入选中态，再点击替补席上的任一球员即放入。选中槽位后再次点击已占用槽位，则该球员回到替补席。
  3. 交换：依次点击两个已占用槽位，两位球员互换，槽位上的位置标签保持不变。
  4. 换阵型：切换阵型时按位置靠近程度重建槽位，并尽量保留已落位球员；无法映射的球员回到替补席。

可视化规则

  • 槽位显示三部分：头像或号码圆泡、姓名标签、位置缩写。位置缩写始终取自槽位而非球员主位置。
  • 空槽位以虚线圆 + 位置缩写显示，明确告诉用户这里缺谁。
  • 替补席实时显示未落位球员，已落位者在替补席置灰，避免重复放入。
  • 顶部显示「已落位 x / n」，n 等于该阵型槽位总数。

边界

  • 槽位未填满时允许进入预览，但「导出站位图」不可用，并提示还差几个槽位。
  • 同一球员不会同时出现在两个槽位；试图重复放入时提示「该球员已在场上」。
  • 该阵型槽位少于在场球员时，多出的球员留在替补席，不自动覆盖已落位者。

F6 播出站位图预览

预览画面就是导播最终使用的画面，因此它需要在不进入图片编辑器的前提下，回答「这张图能不能上」。

画面构成

  • 俯视半场，主队由下向上进攻；球员以圆形头像、姓名、号码与位置排布。
  • 右下角（纵向时为底部）为球队信息条：球队名称、赛制、阵型、主客身份、PRE-MATCH 标识。
  • 队长在头像角上显示 C 标；未上传照片者显示球队主色底与号码。

可切换项

选项默认影响
横向 / 纵向横向纵向用于竖屏播出与更衣室大屏；只改变画幅与标注排布，不影响槽位关系。
显示头像开关闭后使用号码圆泡，适合照片未齐时的临时播报。
显示姓名开关闭后仅保留号码与位置，用于小尺寸画面。

任一切换项立即重绘画面，不等候保存。预览中的画面与导出的画面必须一致，不允许存在「预览好看、导出错位」的差异。

F7 导出与交接

完成链路交付两种产物：给人看的画面，给系统用的名单。

导出的前置条件

  • 球队名称非空。
  • 在场球员人数等于所选人数，且每个槽位都有球员。
  • 号码无重复；队长不超过一人。
  • 以上不满足时导出按钮不可用，并在按钮旁给出唯一原因。

产物

产物内容用途
站位图图片当前预览画面的静态图，画幅与视角跟随预览设置直接贴入赛前介绍模板或投屏
名单 JSON球队信息、人数、阵型、槽位坐标、球员字段（不含照片二进制）交给字幕系统、数据组或下一场复用

交接与重新导出

导出成功后记录导出时间与当前画面配置。之后修改任何字段，系统提示「档案已修改，画面需重新导出」，但不清除已有导出文件。

  • 「推送导播台」本期不接入真实接口，点击后明确提示「本期未接入，请使用导出文件」。[TBD]
  • 导出失败（渲染或写入异常）时保留当前状态，允许重试；连续失败提示改为导出 JSON 作为兜底。

F8 · P1 批量粘贴名单

名单常在聊天窗口中以「7 张三 5 李四」的形式传来。逐行录入 11 人约需 3–5 分钟，批量粘贴可压缩到几十秒，因此在 P0 稳定后优先补齐。

  • 支持「号码 + 空格 + 姓名」每行一人，也兼容「姓名 + 号码」与逗号分隔。
  • 解析后进入预览表，逐行确认、修正后再写入名单，不直接覆盖现有球员。
  • 无法识别的行集中列在底部，由用户手动处理，不静默丢弃。
  • 位置与队长不作为粘贴内容，粘贴后仍需用户指定；系统可按号码推断门将（1 号）并标注为建议，需用户确认。

状态模型

草稿档案已建立，名单未满
待编排名单通过校验，槽位有空
可导出槽位已满且全部通过
已导出已生成图片与 JSON

状态由数据实时推导，不单独持久化。任何字段变化都会重新推导；从「已导出」变回「可导出」时显示「需重新导出」。

导出规则

  • 文件命名：{三字代码}_{赛制}_{阵型}.png 与 {三字代码}_{赛制}_{阵型}.json，三字代码为空时用球队名称。
  • 图片包含预览中的全部可见元素，不包含选中态、虚线空槽、替补席与操作按钮。
  • JSON 中照片仅保留布尔标记 hasPhoto，不内嵌图片数据。
  • 导出不覆盖同名历史文件，由浏览器生成副本命名。
  • 目标分辨率与画幅比例。[TBD]
